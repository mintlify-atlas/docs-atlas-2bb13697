`Validaciones` is the centralised input-validation library for DBOO. All user-facing Swing forms call methods from this class before persisting data to the db4o object database. The class lives in package `Clases` and has no superclass. Most methods are instance methods returning `boolean`; one method — `ValidarCedula` — is also provided as a `static` convenience overload. Regex patterns and calendar logic are defined inline within each method and are documented below.

## Package

```java
package Clases;

import java.util.Date;
import java.util.regex.Matcher;
import java.util.regex.Pattern;
```

## Identity Validation

### ValidarCedula (static)

```java
public static boolean ValidarCedula(String cadena)
```

Trims whitespace from `cadena` and checks whether it is exactly 10 decimal digits. This is the primary validator for the national identification number (cédula ecuatoriana) used across all `Persona` subclasses.

<ParamField path="cadena" type="String" required>
  The raw cédula string entered by the user.
</ParamField>

**Regex:** `[0-9]{10}`

**Returns:** `true` if the string is exactly 10 digits; `false` otherwise.

---

### validarCedula (instance)

```java
public boolean validarCedula(String cadena)
```

Instance-method equivalent of `ValidarCedula`. Uses the same `[0-9]{10}` regex and returns the same result via a boolean flag variable.

<ParamField path="cadena" type="String" required>
  The raw cédula string entered by the user.
</ParamField>

**Regex:** `[0-9]{10}`

**Returns:** `true` if the string is exactly 10 digits; `false` otherwise.

<Note>
  Both `ValidarCedula` (static) and `validarCedula` (instance) apply the same rule. Prefer the static form `Validaciones.ValidarCedula(cedula)` for convenience in form code.
</Note>

### ValidarNomApe

```java
public boolean ValidarNomApe(String cadena)
```

Validates a person's first name or last name. Accepts only alphabetic characters (uppercase and lowercase) and whitespace (to support compound names such as "María José"), with a length constraint of 3 to 30 characters.

<ParamField path="cadena" type="String" required>
  The first name or last name string to validate.
</ParamField>

**Regex:** `[A-Za-z\s]{3,30}`

**Returns:** `true` if the name is 3–30 characters composed only of letters and spaces.

---

### ValidarId

```java
public boolean ValidarId(String cadena)
```

Validates structured identifier codes used as primary keys throughout the system (e.g., `cod_organizador`, `codigo_patri`). The expected format is three uppercase letters, a hyphen, and three digits — for example `ORG-001`.

<ParamField path="cadena" type="String" required>
  The identifier string to validate (e.g., `"ORG-001"`).
</ParamField>

**Regex:** `[A-Z]{3}-\d{3}`

**Returns:** `true` if the string matches the `AAA-000` pattern.

---

### validarPlaca

```java
public boolean validarPlaca(String cadena)
```

Validates an Ecuadorian vehicle licence plate in the format `AAA-0000` (three uppercase letters, hyphen, four digits).

<ParamField path="cadena" type="String" required>
  The licence plate string to validate.
</ParamField>

**Regex:** `^[A-Z]{3}-[0-9]{4}`

**Returns:** `true` if the string matches the plate pattern.

---

### ValidarGenero

```java
public boolean ValidarGenero(String genero)
```

Validates the gender field. Only two values are accepted: `"H"` (hombre / male) or `"M"` (mujer / female), case-insensitively.

<ParamField path="genero" type="String" required>
  The gender string to validate (`"H"` or `"M"`).
</ParamField>

**Logic:** `genero.equalsIgnoreCase("H") || genero.equalsIgnoreCase("M")`

**Returns:** `true` if the string is `"H"` or `"M"` (any case).

## Contact Validation

### ValidarCorreo

```java
public boolean ValidarCorreo(String mail)
```

Validates an email address using a compiled `Pattern` and `Matcher`. The regex enforces standard email structure: local part with alphanumerics and allowed special characters, `@` separator, domain name with optional subdomains, and a top-level domain of 1–30 characters.

<ParamField path="mail" type="String" required>
  The email address string to validate.
</ParamField>

**Regex:**

```java
^[_A-Za-z0-9\-\+]+(\.[_A-Za-z0-9\-]+)*@[A-Za-z0-9\-]+(\.[A-Za-z0-9]+)*(\.[A-Za-z]{1,30})$
```

**Returns:** `true` if the email matches the pattern (using `Matcher.find()`).

### ValidarCiudad

```java
public boolean ValidarCiudad(String ciudad)
```

Validates a city name. Accepts only alphabetic characters and whitespace — no digits or special characters.

<ParamField path="ciudad" type="String" required>
  The city name string to validate.
</ParamField>

**Regex:** `[A-Za-z\s]*`

**Returns:** `true` if the city string contains only letters and spaces (including the empty string due to `*`).

## Date Validation

### ValidarFechaNacimiento

```java
public boolean ValidarFechaNacimiento(int dia, int mes, int anio)
```

Validates a birth date by checking that the month is in range 1–12, then checking the day against the correct upper bound for that month — including leap-year handling for February. The year is referenced but not range-checked beyond the leap-year calculation.

<ParamField path="dia" type="int" required>
  Day of the month (1–31 depending on month).
</ParamField>

<ParamField path="mes" type="int" required>
  Month number (1 = January … 12 = December).
</ParamField>

<ParamField path="anio" type="int" required>
  Four-digit year (e.g., 1990). Used for leap-year calculation on February.
</ParamField>

**Logic summary:**

| Month | Max day |
|-------|---------|
| 1, 3, 5, 7, 8, 10, 12 | 31 |
| 4, 6, 9, 11 | 30 |
| 2 (non-leap) | 28 |
| 2 (leap) | 29 |

Leap year condition: `(anio % 4 == 0 && anio % 100 != 0) || anio % 400 == 0`

**Returns:** `true` if the day/month/year combination is a valid calendar date.

---

### validarFecha

```java
public boolean validarFecha(String cadenaFecha)
```

Validates a date string in ISO 8601 format `yyyy-MM-dd` (e.g., `"2024-07-15"`). Uses a compiled `Pattern` and `Matcher.matches()`.

<ParamField path="cadenaFecha" type="String" required>
  The date string to validate. Must be in `yyyy-MM-dd` format.
</ParamField>

**Regex:** `\d{4}-\d{2}-\d{2}`

**Returns:** `true` if the string matches the four-digit year, two-digit month, two-digit day pattern.

<Note>
  `validarFecha` checks format only — it does not verify that the day/month values are calendar-valid. Combine with `ValidarFechaNacimiento` when strict date correctness is required.
</Note>

## Content Validation

### ValidarContenido

```java
public boolean ValidarContenido(String cadena)
```

Validates free-text content fields (e.g., event descriptions, comments). Allows only alphanumeric characters and whitespace — no punctuation or special characters.

<ParamField path="cadena" type="String" required>
  The content string to validate.
</ParamField>

**Regex:** `^[A-Za-z0-9\s]+$`

**Returns:** `true` if the string contains only letters, digits, and spaces (at least one character).

---

### ValidarPuntuacion

```java
public boolean ValidarPuntuacion(String cadena)
```

Validates a score or rating in the range 0–100 (inclusive). Accepts the literal string `"100"` or any one-to-two digit numeric string.

<ParamField path="cadena" type="String" required>
  The score string to validate (e.g., `"75"`, `"100"`, `"0"`).
</ParamField>

**Regex:** `^(?:100|[0-9]{1,2})$`

**Returns:** `true` if the string represents an integer from 0 to 100.

---

### ValidarEntero

```java
public boolean ValidarEntero(String numero)
```

Validates that a string represents a positive integer. Strips whitespace before matching.

<ParamField path="numero" type="String" required>
  The numeric string to validate.
</ParamField>

**Regex:** `[0-9]+`

**Returns:** `true` if the string (after whitespace removal) contains only digits.

---

### validarDouble

```java
public boolean validarDouble(String numero)
```

Validates a decimal number string with up to three integer digits and an optional decimal part (e.g., `"123.45"`, `"50"`, `"9.9"`). Strips whitespace before matching.

<ParamField path="numero" type="String" required>
  The decimal number string to validate.
</ParamField>

**Regex:** `\d{1,3}(\.\d+)?`

**Returns:** `true` if the string represents a non-negative decimal with 1–3 integer digits.

## Credential Validation

### validarContrasena

```java
public boolean validarContrasena(String contrasena)
```

Validates a login password against a strong-password policy: minimum 8 characters, at least one lowercase letter, at least one uppercase letter, and at least one digit.

<ParamField path="contrasena" type="String" required>
  The password string to validate.
</ParamField>

**Regex:** `^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$`

The lookahead assertions enforce the character-class requirements without anchoring their positions:
- `(?=.*[a-z])` — at least one lowercase letter anywhere
- `(?=.*[A-Z])` — at least one uppercase letter anywhere
- `(?=.*\d)` — at least one digit anywhere
- `.{8,}` — total length at least 8

**Returns:** `true` if the password satisfies all four conditions.
